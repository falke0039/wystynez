# Эталон верхнего меню старого сайта SiteCraft

**Источник эталона:** `p95.htm`, верхний блок страницы услуг.

- Исходный HTML: https://github.com/falke0039/wystynez/blob/main/p95.htm
- Опубликованная страница для визуального сравнения: https://falke0039.github.io/wystynez/p95.htm
- Протокол восстановления: https://github.com/falke0039/wystynez/blob/main/RESTORATION_PROTOCOL.md

## Как использовать

Если на восстанавливаемой странице меню отсутствует, повреждено или отображается неправильно, брать за основу верхний блок меню из `p95.htm` — от внешнего контейнера шириной 1235 px до `div.clearbar` включительно. Переносить его как единый блок, сохраняя вложенность элементов и стили.

## Что нельзя менять без согласования

- порядок и подписи пунктов: «на главную», «природа», «история», «культура», «о нас», «экспозиция», «архив событий», «наши друзья»;
- цвета блоков, ширины и высоты, отступы и разделители;
- классы `p1`, `t13`, `clearbar`;
- адреса ссылок. Относительные ссылки разрешается аккуратно скорректировать только при переносе на страницу с другим уровнем вложенности; назначение ссылки менять нельзя.

## Важное ограничение

Этот эталон фиксирует исходную HTML-разметку, а не подтверждает, что меню сейчас правильно отображается на опубликованном сайте. Правило CSS для `.t13` уже добавлялось, но пользователь не увидел изменений. До объявления ремонта успешным необходимо отдельно проверить источник публикации GitHub Pages и фактическую загрузку `sc-pro/sc.css`.

## Процедура восстановления

1. Скопировать блок меню из исходного `p95.htm`.
2. Сравнить ссылки с контекстом целевой страницы; корректировать только относительные пути при объективной необходимости.
3. Проверить связанные стили и все страницы, использующие общую таблицу CSS, прежде чем менять `sc-pro/sc.css`.
4. Проверить HTML и опубликованный результат. Коммит или успешный workflow сами по себе не доказывают, что меню работает.
5. Записать целевую страницу, изменения, проверки и commit SHA в общий архив музея.
